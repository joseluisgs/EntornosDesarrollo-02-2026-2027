# Práctica 2: Cuestionario de Razonamiento

**Instrucciones:** Responde a cada pregunta explicando tu razonamiento y basándote en la información proporcionada.

---

1.  **Ventajas de un IDE frente a un editor de texto.**
    Un compañero de clase dice que para programar solo necesita el Bloc de Notas y una terminal. Explica por qué un Entorno de Desarrollo Integrado (IDE) como Rider ofrece ventajas significativas frente a un editor de texto plano. Menciona al menos tres componentes esenciales de un IDE y cómo mejoran la productividad del programador.

2.  **Filosofía JetBrains y transición entre IDEs.**
    Trabajas en un proyecto de C# con Rider y tu empresa te asigna a un proyecto de Java que se desarrolla con IntelliJ IDEA. Explica en qué se basa la filosofía JetBrains para que la transición entre ambos IDEs sea sencilla. Describe al menos tres elementos de la interfaz que son comunes y cómo afecta esto a la curva de aprendizaje.

3.  **Diferencias entre Build y Rebuild.**
    Durante el desarrollo de un proyecto, el alumno ejecuta `Build` y funciona correctamente, pero al añadir una nueva dependencia el proyecto falla hasta que ejecuta `Rebuild`. Explica la diferencia entre ambos comandos y por qué en ocasiones es necesario ejecutar una Reconstrucción completa en lugar de una compilación incremental.

4.  **Instalación de herramientas: JDK vs .NET SDK.**
    Para desarrollar en Java se necesita instalar el JDK, y para desarrollar en C# se necesita el .NET SDK. Explica la diferencia entre ambos kits de desarrollo y por qué un IDE como Rider no sustituye la necesidad de instalar el SDK correspondiente.

5.  **Plugins y extensiones: beneficios y riesgos.**
    Un compañero instala 15 plugins en su IDE porque le parecen todos útiles, pero luego queja que el IDE va muy lento. Explica qué son los plugins, cómo pueden mejorar la experiencia de desarrollo y qué riesgos o inconvenientes tiene instalar demasiados.

6.  **Personalización y configuración reproducible.**
    Formateas tu ordenador y pierdes toda la configuración de tu IDE: temas, atajos, extensiones, snippets. Explica qué son los dotfiles y la sincronización de configuración, y cómo podrías haber evitado este problema configurando tu entorno de forma reproducible.

7.  **Refactorización: qué es y por qué importa.**
    Un programador escribe una función de 200 líneas que hace muchas cosas. Explica qué es la refactorización y por qué es una buena práctica mejorar la estructura del código sin cambiar su comportamiento. Menciona al menos dos tipos de refactorización disponibles en Rider y explica en qué consiste cada una.

8.  **Depuración con breakpoints.**
    Tu programa lanza un error en la línea 50, pero la causa real está en la línea 12 donde se asigna un valor incorrecto a una variable. Explica qué es un breakpoint, cómo se usa el modo de depuración y la diferencia entre Step Over, Step Into y Step Out para llegar a encontrar el origen del error.

9.  **Control de versiones integrado en el IDE.**
    Rider y VS Code incluyen integración con Git directamente en el IDE. Explica por qué es importante usar control de versiones durante el desarrollo y qué ventajas tiene usar la integración del IDE en lugar de la línea de comandos para las operaciones básicas de Git (commit, push, pull).

10. **Elección de IDE según el contexto.**
    Un equipo de desarrollo tiene que elegir IDE para un proyecto de C#/.NET que trabajará en Windows, Linux y macOS. Explica por qué Rider podría ser la mejor opción frente a Visual Studio (que solo funciona en Windows) y VS Code (que es más ligero pero menos integrado). Justifica tu respuesta considerando rendimiento, funcionalidades y multiplataforma.
